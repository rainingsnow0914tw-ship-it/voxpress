# VoxPress v0.2 readiness

VoxPress v0.2 is being prepared as a privacy-conscious, maintainable open-source release. This document records the release gates without claiming that an unpublished version is already available.

## Completed in the release branch

- Refactored the Windows hotkey, audio, transcription, paste, configuration, logging, tray, and lifecycle boundaries.
- Added synthetic tests that do not register a global hook, open a microphone, use a real clipboard, or download a model.
- Removed transcript text from console and tray output.
- Added bounded temporary-audio cleanup, metadata-only logs, a single-instance guard, and safer paste/focus handling.
- Added blocking lint, test, and package jobs for CI.
- Added contributor, security, privacy, architecture, changelog, and release documentation.
- Passed 166 synthetic non-live tests locally on 2026-08-12, including a native Win64 `INPUT` ABI-size guard and regressions for hotkey pairing, cancellation, focused-window injection, model-label redaction, shutdown, and exact payload preservation under the optional voice marker.
- Passed the complete public GitHub Actions matrix on Windows with Python 3.10-3.13, blocking Ruff checks, and wheel/source-distribution builds.
- Built candidate wheel/source distributions, installed the wheel in an isolated environment, and scanned both candidate artifacts for private markers and user-data filenames with no findings.
- Completed bounded live acceptance on Windows on 2026-08-12 for the global `Ctrl+Windows` hook, real microphone capture, CUDA `large-v3-turbo` loading (5.606 s), transcription, and `Ctrl+V` delivery into Notepad. Two longer samples (13.49 s and 9.83 s of captured audio) produced 32 and 29 characters in 816 ms and 683 ms, respectively, and both pasted successfully. Three ultra-short attempts returned zero characters. Proper-noun and homophone substitutions were observed, so this is functional evidence rather than an accuracy claim.
- Completed the remaining focus and recovery acceptance with one-process environment overrides rather than persistent config changes. With `strict_focus_guard = true` and a temporary 5,000 ms test delay, two target-window changes were blocked as `PASTE_FOCUS_CHANGED` after 12.97 s / 29-character / 860 ms and 11.13 s / 19-character / 655 ms samples. The maintainer confirmed that the complete result remained available for manual `Ctrl+V` recovery. The 5,000 ms delay was deliberately artificial and is not a normal performance result; the configured default remains 200 ms.
- Completed real `typing` and `hybrid` acceptance with the normal 200 ms delay. A 2.96 s hold-to-talk sample followed the armed-recording-to-stopping release path, produced 8 characters in 848 ms, typed directly, and did not press Enter. A short-tap toggle sample remained recording after the first release, stopped on the second press, and produced 32 characters from 9.91 s of audio in 773 ms with successful direct typing and no Enter.
- Completed tray-initiated graceful shutdown twice. Each observed `shutdown_begin`, hotkey-hook removal, `shutdown_complete`, and zero remaining candidate processes. The private daily-use installation was then restored and independently reported its sound hooks and `Ctrl+Windows` hotkey ready. No transcript content, clipboard content, window title, personal vocabulary, or private audio was added to repository or PR evidence.

## Tested environment and performance evidence

The reproducible live record above used Windows 11 Home 25H2 (build 26200.9168), an Intel Core Ultra 9 185H (16 cores / 22 logical processors), 64 GB RAM, and an NVIDIA GeForce RTX 4070 Laptop GPU with 8 GB VRAM. This is one verified environment, not a minimum requirement or a universal benchmark.

A maintainer collaborator separately reported smooth GPU-accelerated use on a Lenovo system with an RTX 5090. With GPU acceleration disabled on that system, one utterance was reported to take approximately one minute. The CPU, RAM, model, compute type, audio duration, and cold/warm state were not fully recorded, so both Lenovo results remain field observations rather than instrumented benchmarks; the CPU result is not evidence of RTX 5090 performance.

CPU execution is supported, but large models are not recommended on CPU for latency-sensitive interactive dictation. CPU-only users should begin with a smaller model and INT8. Results will vary by hardware, model, settings, audio length, and model-cache state.

## Required before merging the release branch

- Obtain maintainer approval before merging or changing the live installation.

## Remaining before a tagged binary v0.2 release

- Build the Windows executable from the tagged commit and publish its SHA-256 checksum.
- Verify a source install and the packaged executable on a clean Windows account or machine.
- Confirm that release artifacts and documentation contain no personal vocabulary, transcripts, logs, audio, credentials, machine paths, or private assistant behavior.

## Claim boundary

Until the merge gate passes, describe v0.2 as an in-progress release branch. Until the tagged binary gates pass, do not claim that v0.2 is a published binary release or available on PyPI. Do not claim broad adoption or verification on every supported Windows and Python version.
